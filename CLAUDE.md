# Learner Metrics — Claude Code Guide

## Project Overview

Multi-tenant SaaS app for NIH training programs to track grant and publication metrics.

**Stack:** FastAPI + SQLAlchemy 2.0 async + asyncpg + PostgreSQL + Alembic (backend) · React 19 + TypeScript + Vite + TailwindCSS + Zustand (frontend) · Podman/Docker containers

**Ports (dev):** Backend: 8020 · Frontend: 5020 · DB: 5432

## Architecture

### Multi-Tenancy (RLS)
- Every request sets `app.current_tenant` via `SET LOCAL` in the session (see `backend/database.py`)
- PostgreSQL Row-Level Security policies enforce tenant isolation on all data tables
- `X-Tenant-ID` header → middleware → `set_current_tenant()` ContextVar
- Auth endpoints (identify, authenticate) use `get_db_no_rls` to bypass RLS

### RBAC
- Privilege levels: `ADMIN(4) > FULL(3) > PARTIAL(2) > VIEW(1)`
- Stored in `user_unit_assignments` with `is_cascading` and `depth` fields
- `get_unit_privilege(user_id, unit_id, db)` resolves highest privilege via tree_path ancestor walk
- `has_permission("FULL", None)` — FastAPI Depends factory; `None` = tenant-wide check

### Unit Hierarchy
- `tree_path` column: dot-separated UUIDs from root to current unit, e.g. `"root-uuid.dept-uuid.lab-uuid"`
- Ancestors fetched with `WHERE unit_id IN (split tree_path into list)`
- Schema inheritance merges parent fields as read-only in child units

### Auth Flow
1. Frontend: `POST /auth/google/identify` with Google ID token → returns `{identity_id, tenants[]}`
2. User selects tenant
3. Frontend: `POST /auth/google/authenticate` with `{identity_id, tenant_id}` → returns JWT
4. JWT carries `sub` (user_id), `tenant_id`, `exp`
5. All subsequent requests include `Authorization: Bearer <token>` and `X-Tenant-ID: <uuid>`

## Migrations

Migrations live in `backend/alembic/versions/`. Current versions:
1. `001_initial_schema.py` — all tables
2. `002_rls_policies.py` — RLS enable + tenant_isolation policies
3. `003_seed_system_tenant.py` — system tenant seed

To create a new migration after changing `models.py`:
```bash
cd backend && alembic revision --autogenerate -m "add new field"
```

Always review autogenerated migrations before running — Alembic may miss some PostgreSQL-specific constructs (RLS policies, custom types).

## External APIs

### NIH RePORTER
- Endpoint: `https://api.reporter.nih.gov/v2/projects/search`
- No auth required
- Profile lookup: POST with `pi_names` criterion
- Project sync: POST with `pi_profile_ids` + `fiscal_years` (10-year lookback)

### ORCID Public API
- Endpoint: `https://pub.orcid.org/v3.0`
- No auth required for public records
- Headers: `Accept: application/json`
- Search: `GET /search?q=given-names:{first}&family-name:{last}`
- Works: `GET /{orcid-id}/works`

### PubMed E-utilities
- Endpoint: `https://eutils.ncbi.nlm.nih.gov/entrez/eutils`
- Optional `NCBI_API_KEY` in env for higher rate limits (10/s vs 3/s)
- esearch returns PMIDs as JSON; efetch returns XML
- Rate limit: add delays between large batch requests

## Data Model Notes

- `nih_profile_id`, `orcid_id`, `pubmed_query` are **first-class columns on User** (not JSONB attributes) — they are core integration fields
- `publications` table uses `source` enum: `orcid` | `pubmed` | `both` | `manual`
  - When same paper found via both ORCID and PubMed (same PMID or DOI), existing record is updated to `source='both'` — no duplicate stored
- `NIHReporterProject.appl_id` is unique per `(tenant_id, appl_id)` — different tenants can independently track the same NIH grant
- `Publication` has two soft-dedup unique constraints: `(tenant_id, user_id, pmid)` and `(tenant_id, user_id, doi)`
- UUIDs use `uuid6.uuid7()` for time-ordered primary keys (better B-tree index performance)

1. `GET /health` → 200
2. Google login → identify → authenticate → JWT issued
3. Create unit → create user → assign to unit
4. Look up NIH profile → assign → sync projects → view in NIH Grants page
5. Assign ORCID iD → sync → view in Publications page
6. Set PubMed query → sync → publications merged/deduplicated
